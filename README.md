# QASensei pilot

Independent local QA process runner for the four-pillar Sensei pilot. Standalone bootstrap
component. Product implementation and ReviewSensei review
remain separate roles. No cloud effects, recovery activation, releases or PR
approvals are part of this component.

The initial CLI is `python qasensei.py plan|run|report`. The plan binds a clean Git
candidate, checks and fixture bytes. Trusted checks emit one structured JSON
observation; process exit alone is insufficient acceptance evidence.

Use Python 3.11 or newer. No third-party runtime package is required. The canonical packaged
CLI is `qa-sensei`; `sensei-qa` remains a compatibility alias. The source CLI
works directly. Inspect `python qasensei.py capabilities --json` for actual limits.

An operator-reviewed input spec uses this closed shape:

```json
{
  "version": 1,
  "workflow_id": "g34-pilot",
  "repository": "/absolute/clean/candidate",
  "candidate_commit": "40-character-exact-HEAD-SHA",
  "checks": [{
    "id": "G34-baseline",
    "required": true,
    "argv": ["/absolute/current/python", "/absolute/clean/candidate/check_g34.py"],
    "expected": {"boundary": "approved-before-effect", "effect_count": 0},
    "fixtures": ["check_g34.py", "tests/fixtures/g34.json"],
    "timeout_seconds": 30
  }]
}
```

The supported trusted profile is `python-json-check/1`: use the same interpreter
that runs QASensei, and a repository Python script declared in `fixtures`.
Check IDs are the stable criterion IDs. These arguments are a reviewed local
profile, not commands generated by a model at dispatch time. Commands run with
the candidate as cwd and a small environment; all installed Python package
versions, interpreter and Git fingerprints are retained in the plan.

The script must independently assert actual behavior and print exactly one finite
JSON object to stdout. Other diagnostics go to stderr:

```json
{"version":1,"status":"passed","observed":{"boundary":"approved-before-effect","effect_count":0},"effects":[]}
```

Valid check outcomes are `passed`, `failed`, `blocked`, `skipped`, `flaky`, and
`not_run`. A `passed` observation must exactly match the frozen `expected` object,
including JSON types. A check's effect trace must come from the actual fixture;
the runner does not invent effects from a summary. Required missing, skipped or
flaky evidence gives an `incomplete` QA verdict; observed failures give `failed`.
This first implementation emits canonical `passed`; it has no previously stored
`pass` records to migrate.

```sh
python qasensei.py plan --spec spec.json --out /private/qa-plan.json
# Review the complete plan and copy its exact file SHA-256 from the result.
python qasensei.py run --plan /private/qa-plan.json --plan-sha256 SHA --out /private/new-bundle
python qasensei.py report --bundle /private/new-bundle
python qasensei.py gate --bundle /private/new-bundle
```

`run` and `report` return exit 0 when the requested protocol operation completed,
including a completed failed check. Read `verdict` for acceptance. Malformed
inputs, integrity failures and unfinished bundles return 2; a stale candidate or
environment refused before checks returns 3. `gate` additionally returns 1 for a
failed verdict and 2 for incomplete acceptance. No login or provider runs occur.

The bundle preserves `plan.json`, `receipt.json`, `manifest.json`, markers and
content-addressed sanitized logs. Receipts contain CheckSpec digests, candidate
file manifests, environment versions, exact argv/cwd/times/exit, expected and
observed values, effects, per-check results and all six outcome counts. `report`
revalidates hashes and derives results from retained observations; it never
executes a check. Evidence changes are not repaired automatically.

Manager integration uses explicit shared exports:

```sh
python qasensei.py candidate --plan /private/qa-plan.json --base-commit BASE --out /private/candidate.json
python qasensei.py export --bundle /private/new-bundle --candidate /private/candidate.json --task-id qa --suite g34
```

`candidate` emits the Manager's closed `sensei.candidate/1.0` shape. It binds the
exact repository, baseline, candidate commit/tree and binary diff digest. Dirty
and untracked content is refused. `untracked_sha256` hashes compact JSON `[]`;
`fixture_sha256` hashes the sorted unique path-to-file-SHA object from the plan;
`environment_sha256` hashes the complete frozen environment object. These shared
digests use sorted compact finite UTF-8 JSON, Unicode preserved, no trailing LF.
Artifact digests cover exact file bytes, including any final LF.

`export` emits `sensei.qa/1.0`, verifies the supplied shared candidate against those
same rules, and retains exact native receipt and manifest ArtifactRefs. It does
not replace Manager's operation/handoff record or ReviewSensei's verdict. For a
Code handoff, prepare this shared candidate after the source is frozen and before
Manager records the Code candidate; all downstream gates must use identical bytes.

`g34-acceptance.json` freezes intended product checks, all initially `not_run`.
It is an acceptance inventory, not an executable spec or a hosted reproduction.
The product fixture must name the actual guard and record real byte counts and
effect order before implementation is justified.

Run bootstrap controls with `python -m unittest discover -s . -p test_qasensei.py -v`.
